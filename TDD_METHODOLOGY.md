# DeathNote TDD 方法論改進方案

## 一、緩存問題分析與解決方案

### 緩存問題根因
1. **Service Worker 緩存** - `sw.js` 使用 `deathnote-v2` 舊版本名稱
2. **瀏覽器緩存** - 靜態資源被瀏覽器緩存
3. **CDN/代理緩存** - GitHub Pages 可能有中間層緩存
4. **PWA 離線緩存** - 已安裝的 PWA 會繼續使用舊緩存

### 解決方案

#### 1. Service Worker 版本管理
- 每次發布更新 `CACHE_NAME` 版本號
- 版本號規則：`deathnote-v{major}{minor}` (如 v3, v4)

#### 2. HTML 緩存控制
- 生成的 HTML 添加版本查詢參數
- 使用當前時間戳記作為版本號

#### 3. 部署前清理腳本
```bash
# 清理本地 dist 目錄中的緩存文件
rm -rf .DS_Store
```

#### 4. 用戶端解決方案
- 提供「強制刷新」說明文檔
- 在我的頁面添加「清除緩存並刷新」按鈕

## 二、TDD 開發流程改進

### 改進後的 TDD 流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        TDD 開發循環                                        │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  1. 需求分析 (Analyze)                                                 │
│     ├── 理解用戶請求的實際需求                                           │
│     ├── 識別閉環（功能上下游銜接）                                        │
│     └── 識別外部依賴（庫、文檔）                                          │
│                              ↓                                          │
│  2. 測試計劃 (Plan)                                                    │
│     ├── 創建 TODO 清單                                                   │
│     ├── 優先級排序                                                      │
│     └── 識別依賴關係                                                    │
│                              ↓                                          │
│  3. 單元測試 (Test - RED)                                             │
│     ├── 撰寫失敗的測試用例                                               │
│     ├── 測試函數/模組行為                                                │
│     └── 驗證預期輸出                                                    │
│                              ↓                                          │
│  4. 實現功能 (Implement - GREEN)                                      │
│     ├── 最小化實現通過測試                                               │
│     ├── 不做過度設計                                                    │
│     └── 遵循現有代碼風格                                                 │
│                              ↓                                          │
│  5. 重構 (Refactor)                                                   │
│     ├── 改善代碼結構                                                    │
│     ├── 提取公共元件                                                    │
│     └── 優化重複邏輯                                                    │
│                              ↓                                          │
│  6. 生成靜態頁面 (Generate)                                            │
│     ├── 執行 generate.mjs                                              │
│     └── 驗證生成的 HTML                                                │
│                              ↓                                          │
│  7. 本地 QA 測試 (Local QA)                                           │
│     ├── 啟動本地伺服器                                                  │
│     ├── 使用瀏覽器工具測試                                                │
│     ├── 驗證功能閉環                                                    │
│     └── 記錄問題                                                        │
│                              ↓                                          │
│  8. 提交與部署 (Deploy)                                               │
│     ├── Git commit                                                     │
│     ├── 等待 GitHub Pages 部署                                          │
│     ├── 清除瀏覽器緩存（Cmd+Shift+R）                                    │
│     └── 驗證上線版本                                                   │
│                              ↓                                          │
│  9. 生產環境驗證 (Production QA)                                       │
│     ├── 測試關鍵路徑                                                   │
│     ├── 驗證新功能                                                     │
│     └── 記錄問題供下次迭代                                             │
│                                                                     │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 測試驅動開發檢查清單

#### 發布前檢查 (Pre-Deploy Checklist)
- [ ] 所有 TODO 項目已完成
- [ ] 本地生成並通過基本測試
- [ ] 提交代碼包含所有更改
- [ ] GitHub Actions 部署成功

#### 發布後驗證 (Post-Deploy Verification)
- [ ] 使用隱身模式開啟網站（新會話）
- [ ] 測試首頁載入
- [ ] 測試收藏功能
- [ ] 測試閱讀流程
- [ ] 驗證麵包屑導航

### 功能閉環檢查清單

每次實現功能時，必須驗證以下閉環：

```
首頁 → 點擊書籍 → 書籍詳情 → 開始閱讀 → 章節頁 → 返回詳情
     → 收藏按鈕 → 我的頁面收藏列表
     → 分類頁 → 書籍數量 → 書籍詳情
```

## 四、快速開始指南

### 每次開發循環
```bash
# 1. 分析需求並創建 TODO
todowrite([{"content": "...", "status": "in_progress"}])

# 2. 本地開發與測試
bun run generate.mjs
npx serve -p 3000

# 3. 使用瀏覽器工具 QA
# - 測試首頁、分類頁、詳情頁、章節頁
# - 驗證收藏功能、麵包屑導航

# 4. 提交部署
git add -A && git commit -m "feat: 描述" && git push
```

### 緩存問題解決
1. **強制刷新**: Cmd+Shift+R (Mac) / Ctrl+Shift+R (Windows)
2. **隱身模式**: 使用 Chrome 隱身窗口測試
3. **清除緩存**: 開發者工具 → Application → Clear storage
4. **PWA 更新**: 等待 Service Worker 自動更新
